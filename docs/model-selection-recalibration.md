# Embedding 模型选型与重构标定

> 回答四个问题：为什么换模型必须重标定？什么时候会换模型？换成谁（国内可用方案）？换完怎么管（治理）？
> 结论先行：**阈值是贴着模型的打分习惯画的，模型一换全库边界作废——所以选型、标定、退出标准必须在换模型之前就设计好。**
> 调研数据截至 2026-08，来源见文末。

---

## 1. 核心认知：相似度分数没有绝对含义

**0.93 ≠ "93% 相似"。** 向量相似度只是"这个模型在自己打分习惯下给的相对值"。

判卷老师类比：

| | BGE-large-zh | 假想新模型 |
|---|---|---|
| 打分习惯 | 手紧：不相关也给 0.83，一模一样只给 0.97，全挤在 0.83~0.92 窄带 | 可能手松（0.4~0.99 撒开），也可能更紧 |
| 我们的阈值 0.93/0.85 | 贴着这个分布画的线 | **直接套用 = 拿 Celsius 的刻度读 Fahrenheit** |

同一对文本，模型不同分数不同；阈值线从来不属于"重复"这个概念，**属于这个模型的打分习惯**。换模型不重标 → 旧线一刀切下去：新模型手紧则重复问询全变"新问题"（判重瘫痪），手松则新问题全被误判"已合并"（更危险）。

## 2. 什么场景会换模型

### 被动换（不换不行）

| 场景 | 触发 |
|---|---|
| 合规/区域限制 | 境外 API 不可用（Veeva 中国场景）；**数据出境**本身违规（PIPL） |
| 厂商停服 | API 型模型被 sunset，被迫迁移（真实发生过） |
| 客户私有化 | 药企要求数据不出机房（气隙部署），API 型模型出局 |
| 供应链审计 | 甲方问"模型哪家的、依赖境外服务吗" |

### 主动换（换了更好）

| 场景 | 触发 |
|---|---|
| 多语言扩展 | 中英混合（进口药说明书），zh-only 模型不够 |
| 长文本 | 512 tokens 截断成真实瓶颈 |
| 效果升级 | 领域微调模型在黄金集上分数分布更开、三档分得更清——**用数据决定** |
| 成本/延迟 | 库到千万级，换可截断维度/小模型 |
| ⚠️ 同家族版本升级 | bge-v1.5 → v2 也算换模型，分布照样变 |

### 反向认知：不换模型也可能要重标

- **换模型** → 向量全部重建 + 阈值重标（全套）
- **数据分布漂移**（不换模型）→ 向量不动，只重新验证阈值——库里从纯问询扩进大量长文本后，原来的线还合不合适要复测。**标定集要一直攒着，不是换模型那天才有用。**

## 3. 重标定流程（两阶段：标定 ≠ 回归）

关键认知：换模型后拿旧阈值跑回归，失败是预期的——那不叫回归，叫**测量**。

```
① 蓝绿重建：新模型建影子 B 全量重编码（旧影子 A 照常服务）
   ⚠️ 维度可能不同（1024→2560），必须新建 Collection，不能原地升级
② 标定阶段：黄金集角色变身——从"门禁"变"标定集"
   探针自带标签（这对重复/那对新问题）→ 新模型下逐对出分 →
   看两簇分布 → 中间画新线（新 TH_DUP / TH_GRAY）
③ 验证阶段：这才跑回归——新阈值下四类断言全过
④ --record 固化新基线（基线分数本身也全变）
⑤ 切流 → 旧影子留观察期 → 回滚通道随时在
```

**三套数字一起重录**：阈值（判重边界）、漂移容差（±0.03 是按 BGE 拍的，新分布下可能太松）、探针基线。

## 4. 不确定因素与对冲（迁移风险清单）

重来一遍是确定的成本，重来的结果是不确定的。架构设计就是给这个不确定事件买保险：

| 不确定因素 | 风险 | 对冲 |
|---|---|---|
| 新模型分数分布未知 | 重画线前谁也不知道宽窄 | 标定集先测分布再定线 |
| **最坏：三档分不开** | 重复/新问题分数簇重叠，画不出干净线 | **退出标准**：类间距离不够就换候选模型，不硬标 |
| 漂移容差失效 | 新分布下 ±0.03 比簇间距还大，断言名存实亡 | 三套数字一起重录 |
| 标定样本太薄 | 几对样本画两条线，边界一歪全错 | 扩标定集（黄金集扩充的真正用途） |
| 维度不同 | 1024→768/2560，schema 都变 | 蓝绿必须新建 Collection |
| 编码习惯不同 | 有的模型查询侧要加指令前缀，读写路径不镜像就废 | 军规"写入/查询同一路径" |
| 中文口语表现未知 | 商品名/错别字（立普妥/二甲双瓜）跑分前没人打包票 | 归一层先映射，减少模型要猜的 |
| 未知的未知 | 标定集没覆盖的真实查询翻车 | 旧影子观察期 + 灰度切流 + 回滚 |

**最大风险不是重编码的算力**（那是体力活），是**新模型在我们的数据上可能根本分不出三档**——所以迁移方案必须有明确的退出标准，不能默认换过去一定行。

## 5. 岗位边界：应用层评测 vs 模型层微调

| | 改模型（算法团队） | 用模型（本 PoC 所在层） |
|---|---|---|
| 动作 | 训练、微调、改权重 | 评测、选型、标定阈值 |
| 类比 | 造发动机 | 试驾验收：定验收标准、看指标 |

重标定全程不碰模型权重——模型是黑盒，拿标定集（砝码）量它的打分习惯然后画线，和"给新数据库做压测定验收标准"同一性质，属于应用层的标准职责范围。

微调登场的时机 = 退出标准触发之后：

```
标定 → 三档分不开 → 两条路：
  A（应用层权限内）：换下一个候选模型
  B（交给算法团队）：模型其他维度都满意（私有化/中文好/便宜），
     就是分不开 → 领域微调。他们改权重，我们出考题——
     标定集就是微调的验收标准："重复对拉到 X 区间、新问题压到 Y 区间"
```

**边界原则**：模型层的职责明确划出，不越界；但选型评测的工程质量拉到满——微调什么时候该用、拿什么数据驱动、怎么验收，由应用层定义；训练本身不是应用层的职责。边界两边的协作接口（标定集）由应用层设计并维护。

## 6. 国内可用 Embedding 方案梳理（2026-08）

### 候选对比

| 模型 | 参数量 | 维度 | 最大长度 | 协议 | 定位 |
|---|---|---|---|---|---|
| **bge-large-zh-v1.5**（本 PoC 现役） | 326M | 1024 | 512 | MIT | 中文生产首选：质量/成本/生态三角平衡 |
| **BGE-M3** | 568M | 1024 | 8192 | MIT | 长文本/多语言/**dense+sparse+multi-vector 一体** |
| **Qwen3-Embedding-4B/8B** | 4B/8B | 2560/4096 | 32K | Apache 2.0 | 2025 开源第一梯队，多语言榜登顶，支持 MRL 可变维度 + 指令感知；配套 Qwen3-Reranker |
| **gte-Qwen2-1.5B**（阿里） | 1.5B | 1536 | 32K | Apache 2.0 | 语义复杂的医疗/法律长文本 |
| bge-small-zh / text2vec | ~100M | 512/768 | 512 | MIT | 轻量/CPU 边缘部署 |
| ~~Conan-embedding（腾讯）~~ | — | — | — | ⚠️ **CC BY-NC 禁商用** | C-MTEB 分高但**药企生产不可用** |
| 医疗专用（AQ-MedAI Diver-Retriever 等） | 1.7B/4B | — | — | 待核 | 2026 新出现，医疗检索专项，值得跟踪 |

### 两条一票否决项（比跑分更重要）

1. **协议**：Conan-embedding 这类 CC BY-NC 在 C-MTEB 再靠前，商用场景直接出局——选型第一步查协议不是查分数
2. **数据出境**：OpenAI text-embedding-3 等境外闭源 API，把药企文本发出去本身就是 PIPL 违规——**私有化可部署的开源模型是药企场景的入场券，不是加分项**

### 选型决策树（不允许数据出境前提）

```
单次查询 ≤ 512 token？
├─ 是 ─┬─ 预算充裕追 SOTA → Qwen3-Embedding-4B
│      └─ 默认落点        → bge-large-zh-v1.5
└─ 否（长文档/中英混合）  → BGE-M3
三档分不开 → 触发退出标准 → 领域 LoRA 微调（交算法团队）
```

**评估方法警示**：不只看 MTEB/CMTEB 排行榜——必须在自己业务数据上跑标定集（Hit@K、三档分布），排行榜分数高不等于在你的药品名/口语/错别字数据上分得开。**这正是"标定集常备"的又一个理由。**

### 部署要点

- 推理框架：HuggingFace TEI / vLLM / Triton 三选一
- 资源：BGE-M3（568M）单张中端 GPU 约 800 QPS；Qwen3-Embedding-4B 需高端 GPU，成本随参数线性涨
- 典型低成本栈：Qwen3-7B（4bit 量化，8GB 显存）+ BGE-M3 + Milvus

## 7. 结合 Veeva 中国场景的选型结论

把 Veeva 的约束（调研文档 2.5）和用户需求叠到候选模型上：

| Veeva 中国约束 | 对选型的含义 | 结论 |
|---|---|---|
| Claude/Bedrock 不可用，数据不出境 | embedding 必须私有化开源 | 排除全部境外 API；BGE/Qwen3 系入围 |
| 多租户 SaaS，药企客户审计 | 协议必须可商用 | Conan（NC 协议）出局；MIT/Apache 入围 |
| 进口药说明书=中英混合 | zh-only 模型有天花板 | **BGE-M3 是最优平衡点**（8192 长度+多语言+sparse 一体） |
| 判重三档是核心机制（GVP 合规） | 模型必须在自家数据上三档分得出 | 最终拍板靠标定集实测，不靠排行榜 |
| 混合检索路线（2.6③） | sparse 输出原生支持最好 | M3 单模型三路输出，免维护两套索引；或 Qwen3-Embedding + BM25 |
| 客户私有化部署能力 | 模型要能在中端 GPU 跑 | 8B 以上模型对小客户是负担，M3（568M）部署门槛低 |

**一句话结论**：默认 **BGE-M3**（多语言+长文本+混合检索一体，协议干净，部署门槛低）；追极限效果且预算充裕上 **Qwen3-Embedding-4B + Qwen3-Reranker**（顺手把 Reranker 层也补齐）；zh-only 老系统维持 **bge-large-zh-v1.5** 不动。**无论选谁，最终拍板的不是这份对比表，是标定集在自家数据上的三档分布实测。**

## 9. 模型治理：升级时机 / 版本合规 / 客户自带模型

> 选型与标定回答"怎么选、怎么换"；本节回答"怎么管"——GxP 语境下模型是**影响产品质量的受控组件**，管理强度与代码依赖同级甚至更严。

### 9.1 什么时候升级：变更控制事件，不是技术冲动

| 类型 | 内容 |
|---|---|
| 定期评审（计划内） | 固定节奏（如每季度）拿新候选模型跑黄金集——**只是测量不是要换**。三档分布明显更开、或有真实业务需求（多语言/长文本），才启动变更。测完不换是正常结果，记录存档 |
| 事件驱动（计划外） | 安全漏洞、业务扩张（中英混合文档）、成本压力、被动触发（停服/私有化要求，见第 2 节） |

**核心原则：收益必须大于重标定成本才换。** 换一次的隐性成本 = 阈值/容差/基线重录 + 回归验证 + 观察期人力；新模型只好 2% 就不换。受控系统中模型版本默认冻结，仅在评审确认收益覆盖迁移成本时启动变更。

### 9.2 版本合规可审计：模型版本进审计链

| 要求 | 做法 |
|---|---|
| 版本钉死 | 精确版本号 + **权重文件 SHA-256 校验和**——防"同名不同物"（不同渠道权重细微差异会导致分数分布漂移） |
| 来源与协议存档 | 下载来源、协议文本（MIT/Apache）归档，供审计核查使用权 |
| **答案可复现** | 某次检索结果 = 模型版本 × 阈值 × 数据快照共同产生。审计要重现历史答复依据，必须知道当时的模型版本——**黄金集基线须记录模型版本字段**（当前 golden_set.json 尚未记录，属已知缺口，补强计划中修复） |
| 变更留痕 | 每次变更：变更单 → 标定报告 → 回归报告 → 审批人 → 切流时间全留档。回归报告即 CSV 验证包的一部分 |

### 9.3 客户自带模型（BYOM）：Veeva 路线就是 LLM-agnostic

客户指定模型是真实需求（Veeva 平台即支持客户自带模型），带来三个架构后果：

1. **阈值按租户/模型隔离**——阈值属于"模型×数据分布"，租户各自标定各自存。阈值从代码常量下沉为**租户配置**（与设计文档 6.11"权重配置化"同一改造方向）
2. **影子按租户/模型隔离**——不同模型维度/分布不同，不可混住同一 Collection。按租户分 Collection 或 partition_key（接调研文档 2.5 多租户行）
3. **自带模型必须过平台验收门禁**——"模型可以带，上线前必须在你的数据上跑通平台黄金集验证包"。**模型归客户，验证标准归平台**——验证能力因此成为平台的核心资产之一

责任边界须合同前置：客户自选境外 API 模型的数据出境合规责任归客户；平台提供私有化部署选项即尽到义务。

> 第 3 节是方法论，本节是操作层：换模型/重标阈值时照此执行。标注【待做】的条目为已识别技术债，见 A.5。

### 流程总览：重标定四级验证门禁（标定 → 定线 → 终审 → 切流）

> 新构建的向量集与重标定配置必须逐级通过四级门禁才能接触查询流量。
> 四级门禁的方法论谱系（V 模型 OQ/PQ、SR 11-7 有效质疑、蓝绿部署、GAMP 5/CSA）与 Veeva 实践对照见调研文档 2.7。

```
 ┌────────────────────────────────────────────────────────────────────────────┐
 │ 触发事件：换模型 │ 回归漂移报警 │ badcase 积累 │ 定期评审（结论可以是"维持不变"） │
 └───────────────────────────────┬────────────────────────────────────────────┘
                                 ▼
       ① 标定测量（数据说话，机器不决策）        scripts/calibrate.py
       标注对（只增不改） → 编码 → 两簇分布直方图
             │
             ├─ 绝对判定：F1<0.7 或 Youden<0.2（语种/领域不适配）
             │     → ⚠ 退出：换候选模型 或 标定集移交算法团队微调
             │
             ├─ 相对判定：F1/Youden/中位间隔 不劣于现役 → 放行（A.2 实测修正）
             │
             └─ 输出：方案 ②谷点 / ③F1+Youden / ⑤P5 三条建议线 + 误判清单
                                 ▼
       ② 人工判断（业务担责，数据只给候选）
       选线 + margin：参考误判清单的业务严重性、灰色带人力可承受度
       改 config/thresholds.yaml —— 每条线注释写清取值理由
                                 ▼
       ③ 独立终审（验证与标定分离）              scripts/regression.py --rebaseline
       黄金集端到端复核：档位断言强制 / 漂移豁免（换模型后必然漂移）
             │
             ├─ 有错档 → 回到 ② 调线（2026-08-17 实测：0.80/0.60 → 0.85/0.70，
             │            "抗生素泛化问"差点绕过人工闸被拦截，见附录 C.3）
             ▼
       ④ 生效与留痕（证据链闭合）
       阈值 yaml（含理由注释）→ 基线重录（_baseline_recorded 刷新）
       → 模型版本三方一致性校验（golden_set ↔ yaml ↔ 模型目录）
                                 ▼
       ⑤ 日常运行（受控状态）
       回归门禁随入库/变更触发；复评触发条件回到顶部
```

两个结构性设计要点：

1. **①和③必须分离**——标定和终审用两套数据（标注对 vs 黄金集探针）、两个入口（calibrate vs regression），防止"拿出题人的答案考试"。代理指标与真实检索分存在 0.05~0.10 系统偏差（附录 C.3），靠这个分离才能抓到
2. **②是人、不是机器**——calibrate.py 只输出建议线，从不自写配置。"改配置"必须由人完成并留下理由注释，这个判断点就是审计时的责任锚点

**GVP 审计四问与证据载体对照**：

| 审计问题 | 证据载体 |
|---|---|
| ① 决策依据是否记录在案？ | 附录 C 实测表 + regression 输出 + thresholds.yaml 取值理由注释 |
| ② 方法是否预先定义？ | 本 runbook（先于执行冻结，A.1 七步 + A.2 判据） |
| ③ 当时认知水平下是否合理？ | 修正过程完整记录（C.3）；已知缺口诚实标注（thresholds.yaml 的 case_report ⚠️ 注释） |
| ④ 变更是否走控制？ | 模型版本钉死（三方校验）+ 基线重录 + 复评触发条件清单 |

### A.2 分布判断标准（两簇"分不开"怎么量化）

- **可分**：重复对最低分 > 新问题最高分，且间距 ≥ 簇内波动宽度的 2 倍——两条阈值线（dup/new）有地方放
- **灰色**：两簇边缘重叠但主体可分——阈值照画，灰色带放宽，更多人工作闸（业务上可接受，人工闸就是干这个的）
- **不可分（退出）**：两簇大面积重叠，任何画线都导致误判率不可接受 → 换模型或微调，不硬标
- **辅助指标**：同模型对比看"簇间距/压缩带宽度"，新模型该比值显著更大才值得换

**实测修正（附录 C，2026-08-17）**：标定集含一字之差难负样本时（如红霉素/克拉霉素），任何纯向量模型的两簇都会大面积重叠——包括现役生产模型。因此绝对标准只对"模型是否适合该语种/领域"有效（负对照场景：英文模型编中文，F1 峰值 < 0.7、Youden < 0.2，直接退出）；候选模型与现役同族时改用**相对判定**：F1、Youden、正/负簇中位间隔三者综合不劣于现役即放行，分数刻度差异按第 1 节处理（三套数字重录）。

### A.6 操作纪律与决策表（2026-08-25 客户标定演练修订）

> 来源：docs/drill-customer-calibration-2026-08-25.md。演练抓到的三个流程洞，修复成文于此。

**纪律 1：理由栏禁止预填。** `set_threshold.py --reason` 必须由操作人按**实际结果**当场填写，禁止预先拟好模板照抄。演练中预填的"终审未过"与实际结果（通过）不符，且审计表只增不改、错误理由永久留痕——理由写错比不写更糟，它污染的是证据链本身。

**纪律 2：演练/变更后对账断言是收工条件。** 任何阈值操作序列结束后，必须跑 `scripts/reconcile_thresholds.py`，DB 全部锚定键 == `config/threshold_anchors.yaml` 才允许收工。回归输出对阈值不敏感（score 列与阈值无关），行为测试发现不了配置漂移——混合态（一半演练值一半现役值）只有对账能抓到。

**纪律 3：决策表预先定义，禁止现场发挥。** 标定推荐值与现役值的处置规则：

| 情形 | 处置 |
|---|---|
| 推荐值 == 现役值（或差异 < 0.01） | 不动作，记录"评审通过维持现状" |
| 推荐值 ≠ 现役值，回归终审红 | 保留现役值，推荐值入 badcase 分析 |
| 推荐值 ≠ 现役值，回归终审绿 | **取安全余量更大者**（比较关键探针到阈值的 margin，如格华止 0.067 vs 0.0036）；两边余量都可接受时，默认保留现役值（变更本身有成本） |
| 两簇不可分（F1 < 0.70） | 不定线，换候选模型或标定集移交算法团队 |

"回归绿就采纳推荐值"不是默认动作——黄金集接受区往往比标定建议宽，两个值都能过时，margin 才是裁判。

## 附录 B：阈值标定方案对比与场景适配

> 回答"阈值边界怎么定"：六个方案的光谱、本 PoC 用了哪个、不同业务场景为什么用不同方案。

### B.1 六个方案

| 方案 | 怎么画线 | 数据需求 | 可审计性 | 适用场景 |
|---|---|---|---|---|
| ① 专家经验拍值 | 领域专家直接给数 | 无 | 弱（无法复现） | 冷启动、零标注数据 |
| ② 分布目视法 | 标注对出分→直方图→缝里画线 | 少（10~30 对） | 强（分布图即证据） | PoC/小数据（**本 PoC 现状**） |
| ③ 统计最优法 | 扫描候选线取 F1 / Youden's J 最大 | 中（30+ 对） | 强（指标可复算） | 有标注集的生产系统 |
| ④ 代价敏感法 | 给两类错误定代价，最小化期望代价 | 中+业务代价评估 | 强（代价表即依据） | 错误代价不对称场景（PV 并案） |
| ⑤ 分位数法 | dup 分布 P1 / new 分布 P99 | 中 | 强 | 分布偏态时更稳 |
| ⑥ 学习式决策面 | logistic 回归/小模型学边界 | 大（100+ 对） | 弱（GxP 场景吃亏） | 数据充足追精度 |

### B.2 按业务场景选方案（本系统已两套并存）

| 场景 | 错误代价结构 | 方案选择 | 本 PoC 实例 |
|---|---|---|---|
| 问询判重（MI 热线） | 对称（误判重复≈误判新问题，都是操作级小错） | ②+③ 均衡 | 纯向量阈值 0.85/0.70（现役，2026-08-17 重标定） |
| 病例并案（PV，GVP 监管） | **不对称**（误并案=病例少报的合规风险；漏并案=信号稀释） | **④ 代价敏感**：先与业务方定两类错误的代价表，再画线——线的位置是业务决策，技术负责算清 | 混合分阈值 0.87/0.78（现役，2026-08-19 重锚） |
| 检索相关性门槛 | 非二分类，是召回门 | Hit@K 曲线驱动（黄金集跑 Hit@5） | 6.2"分数只当门槛" |

**灰色带宽度是业务参数**：带宽 = 进人工闸的比例——宽度是人工审核人力配置的函数，由团队产能反推，不是技术指标。

### B.3 本 PoC 的诚实状态

- **已用**：①（前期项目经验值迁移）+ ②（本库分布确认）——冷启动组合，合理但未与其他方案正式对比
- **未做**：③④⑤ 的正式对比——calibrate.py（A.5③）会同时输出 ②③⑤ 三条建议线补上；④ 的代价表需业务方输入，PoC 阶段以对称近似
- **不适用**：⑥ 数据量级不够（需要 100+ 标注对），且 GxP 场景可解释性优先，学习式决策面天然吃亏

### B.4 GxP 关键点：方案选择本身要留痕

审计的问题不是"为什么是 0.93"，是"**这条线怎么产生的、用什么数据、什么方法、谁批的**"。标定报告必须记录：选用方案 + 标定数据集版本 + 分布图/指标 + 审批人。选哪个方案都可以，**说不清怎么来的才不行**。

## 附录 C：标定实测记录（2026-08-17，三模型对比）

calibrate.py（A.5③）落地后，用 config/calibration_pairs.json（24 对人工标注：正 12 / 负 12，含 6 对难负样本）对三个模型做了对比标定。指标含义：F1 峰值 = 所有候选阈值上"判重精确率与召回率调和平均"的最高点；Youden 指数 = 召回率 + 特异度 − 1，越接近 1 分离越好、接近 0 等于随机猜。

### C.1 实测数据

| 指标 | MiniLM-L6-v2（负对照，英文模型） | bge-small-zh-v1.5（512 维） | bge-large-zh-v1.5（现役，1024 维） |
|---|---|---|---|
| F1 峰值 | 0.667 | **0.783** | **0.783** |
| Youden 指数 | 0.167 | **0.583** | **0.583** |
| 统计最优线（方案③） | 0.170（无意义） | 0.7616 | 0.8959 |
| 正簇中位数 | 0.8686 | 0.8457 | 0.9248 |
| 负簇中位数 | 0.8649 | 0.6708 | 0.8348 |
| 中位间隔（正−负） | 0.004 | **0.175** | 0.090 |
| 负簇 max（误判重复风险源） | 0.9996 | 0.9408 | 0.9585 |
| 正簇 min（漏判重复风险源） | 0.1700 | 0.4761 | 0.7498 |

### C.2 三个结论

**① 退出标准应做相对判定，不设绝对及格线。** 严格按"两簇重叠即不可分"的绝对标准，三个模型全部触发退出——包括现役 bge-large。根因是标定集里的难负样本（如"阿托伐他汀+红霉素" vs "阿托伐他汀+克拉霉素"，一字之差，bge-large 下余弦 0.9585，比部分正样本对还高）：**纯向量相似度对一字之差的药物组合存在区分上限，与模型规模无关**。因此标定的正确用法是候选 vs 现役的相对比较（F1/Youden/中位间隔三者综合），而不是对每个模型套同一条绝对线。bge-small 三项指标与现役打平、中位间隔更大（0.175 vs 0.090），判定合格放行。

**② 同一可分性，两套数字——分数刻度是模型属性。** bge-small 与 bge-large 分离能力相当（F1/Youden 相同），但最优阈值线分别是 0.7616 和 0.8959，相差 0.13。直接验证了第 1 节的论断：相似度分数没有绝对含义，阈值是模型打分习惯的属性，换模型必须向量、阈值、基线三套数字一起重录，任何一套沿用旧值都会系统性误判。

**③ 灰色带 + 人工闸是架构必需品，不是权宜之计。** 两个 BGE 模型都无法在向量层面分开难负样本（负簇 max 均超过任何合理的自动判重线），意味着总会有一小部分问询的相似度高到像重复、实际是新问题。处置方式只有两种：灰色带转人工，或引入向量之外的信号（如归一层提取的药品集合做规则护栏：药品集合不同则禁止自动判 duplicate）。本 PoC 采用前者；后者列为生产化候选增强。这个结论从定性论述变成了有实测数据支撑的架构决策。

### C.3 回归终审对阈值初值的修正（两阶段分工的实测依据）

标定（对余弦代理）给出的初值 duplicate=0.80 / new=0.60，切流后黄金集回归首轮即抓到 2 条例问探针错档：

| 探针 | 期望档 | 实际检索分 | 初值下的误判 |
|---|---|---|---|
| 立普妥能和抗生素一起吃吗 | gray | 0.8098 | ≥0.80 误判 duplicate——泛化问（抗生素≠红霉素）会绕过人工闸直接复用红霉素答案 |
| 二甲双瓜缓释片怎么吃 | new | 0.6450 | ≥0.60 误判 gray——用法类新问题被拖进人工闸 |

9 条探针的检索分把两条线的可行区间完全卡死：duplicate ∈ (0.8098, 0.9328]，new ∈ (0.6450, 0.7673]。终审取值 **duplicate=0.85 / new=0.70**，全档通过后重录基线。结论：**对余弦代理定方向、定初值，端到端回归定终值**——两轮间隔 0.05~0.10 的系统性偏差，来自代理指标与真实 top1 检索的路径差异（底库过滤、归一化、候选竞争）。相对现役 bge-large 的 0.93/0.85，新模型阈值整体下移 0.08~0.15，与 C.1 的分数刻度差异互相印证。

### C.4 数据诚实标注

- 上表全部为 2026-08-17 在本机（Mac，CPU 推理）对 calibration_pairs.json v1（24 对）的实测值，可用 `python scripts/calibrate.py --model-path <模型路径>` 复现
- 标定指标基于标注对的直接余弦相似度，是生产 top1 检索分数的严格代理（更苛刻）；生产最终判定以黄金集回归（scripts/regression.py）的端到端结果为准
- 24 对的样本量下，单对误判影响 F1 约 0.04，指标读数应按区间理解而非精确点值
