# 生命科学 RAG PoC · 方案概述

> 全仓库导览：定位、架构、关键指标、核心能力与设计细节。
> 完整论证见各专题文档（末尾索引）。数据为仿真样本，架构与流程按生产标准设计。

---

## 1. 总览

### 1.1 定位

面向药企医学信息（MI）/ 药物警戒（PV）场景的知识检索与答复起草系统 PoC。
验证目标不是"能搜到"，而是 **GxP 合规约束下的检索与生成可信度**：可追溯、可审计、可持续更新。

### 1.2 架构一句话

**MySQL 是源（真相/审计/重建），Milvus 是影子（可重建的检索视图）**——写入治理在源层，检索性能在影子，影子随时可全量重建。

```
多格式文档/事件流
   → 归一层（商品名/错别字→通用名，先于编码）
   → MySQL 源层（状态机：现行/作废/已合并/草稿）
   → 增量同步（只放行"现行"）→ Milvus 影子
   → 多路召回 → 权威×角色加权融合 → 引用溯源输出
   → 生成层：PII 脱敏 → 判重短路 → 资格闸 → 覆盖核对
     → LLM 起草（JSON 契约）→ 引用断言 → 五终态路由
   全程门禁：黄金集回归 + 生成层冒烟 + 阈值对账 + 每日持续验证
```

### 1.3 关键指标（全部实测）

| 指标 | 数值 |
|---|---|
| 文档 Collection | 4（说明书/指南/论文/病例）+ 2 事件流（问询/病例上报） |
| 检索黄金集 | 12 条探针（10 问询 + 2 文档），四类断言，回归 12/12 全绿 |
| 生成层冒烟 | 6 条探针断言五终态路由，6/6 全绿（gp-2.4） |
| 病例并案标定 | 14 对标注 14/14 全绿（三道硬否决 + 阈值 0.87/0.78） |
| PII 对抗探针 | 20 条（含误报防线），20/20 全绿 |
| 阈值对账 | 7 个锚定键 DB 实测值全绿（reconcile_thresholds.py） |
| 判重修正 | 只编码判别字段：重复问询相似度 0.8442 → **0.9769** |
| 混合判重 | 向量+四要素规则：真重复病例 0.8844 → **0.9422** 正确并案 |
| 版本防线 | 旧版以 0.8081 vs 0.8026 噪声分差抢 top1，被**版本断言**拦截 |

### 1.4 核心能力（均已验证）

| 能力 | 场景 | 机制 |
|---|---|---|
| 问询判重三档 | MI 热线 | 归一 → ≥0.85 复用 / 0.70~0.85 人工闸 / <0.70 新问题 |
| 多渠道病例并案 | PV（GVP Module VI 要求） | 向量粗筛 + 四要素规则精排 + 三道硬否决 |
| 版本作废管理 | 说明书改版 | 旧版标作废不删（审计），影子精准摘除，版本断言兜底 |
| 角色画像视图 | 热线/医学官/PV | 同一查询三种排序，权威权重×角色 boost |
| 答复起草（辅助模式） | MI 答复 | grounded JSON 契约 + 逐实体覆盖核对 + 引用断言 + 五终态，机器只起草不发出 |

### 1.5 五条核心设计原则

1. **入库 ≠ 生效**——回归过了才算生效
2. **状态机即检索资格**——作废/草稿物理不进影子，不是查询时过滤
3. **一个用途一根向量**——判重只编码判别字段，展示内容进 payload
4. **分数只是门槛**——高分段是噪声，门槛之上排序是业务问题（权威>角色>版本）
5. **阈值是实测标定的**——只对当前模型×当前数据分布有效，换模型全库重标

## 2. 设计细节

### 2.1 数据模型

**A 类·文档**（策展式入库，走版本管理）：`drug_inserts` 说明书（A级）/ `guidelines` 指南（A-级）/ `clinical_papers` 论文（B级）/ `competitor_inserts` 竞品摘要（B级，规划中）
**B 类·事件流**（流式入库，判重+人工确认）：`mi_inquiries` 问询（C→B）/ `case_reports` 病例（C级）

拆块：按结构拆不按长度切——说明书按 24 项法定章节、论文按 IMRaD、指南按单条推荐意见、病例按 SOAP。每块带【药名】【章节】前缀 + doc_type/section/authority/version 元数据。

### 2.2 检索链路

编码（与入库同模型同归一）→ 4 库并行召回 top5 → 权威×角色加权融合 → 引用溯源输出（文档名/章节/权威级/版本/分数）。
**为什么不用 RRF**：RRF 治多通道尺度不可比，本 PoC 单通道同模型分数可比；且"相关性碾压时低权威能翻身"需要分数幅度，RRF 的 rank-only 恰好抹掉该信息。混合检索上线后 RRF 在通道融合层引入，与业务加权串联（详见设计文档 6.11）。

### 2.3 生成层与输出验证

本地 Ollama qwen3:4b（temperature=0、digest 留痕、PROMPT_VERSION 受控）。草稿输出为
JSON 结构契约（gp-2.4）：`coverage`（逐实体覆盖核对，覆盖不全必须拒答）+ `refusal` /
`reason` / `statements[text, citations]`——覆盖核对结果与拒答标志的一致性是机器可判的
硬断言。引用校验拦截：无引用、编号越界（幻觉可探测形态）、覆盖违规、解析失败，有界
重试 ≤2 次后转人工。五终态：标准答案短路 / 资格闸判拒 / 覆盖缺口 / 草稿过（带强制
复核后缀）/ 转人工。语义忠实度留人工复核——机器不越这条线。

### 2.4 质量保障体系

- **事前**：覆盖率对账（问询/病例涉及的药品 vs 库中说明书，缺口出工单）
- **事中**：召回缺口明示降级（"⚠️ 库中暂无【X】说明书原文"，不静默凑合）
- **事后**：补库闭环 + 黄金集回归（四类断言：归一/档位/漂移≤0.03/版本）+ 生成层冒烟（五终态路由）
- **持续**：每日定时全量验证（scheduled_verification.py，绿/红/incomplete 三态 + 留痕 + 异常通知）
- **兜底**：影子全量蓝绿重建（新建→回归→切流→旧影子留观察期）

### 2.5 实测驱动的设计迭代（18 条速览）

| # | 迭代 | 一句话 |
|---|---|---|
| 6.1 | 判重向量只编码判别字段 | 带答案编码 0.8442→只编码问题 0.9769 |
| 6.2 | 高分段分数是噪声 | 分数降级为门槛，排序交业务规则 |
| 6.3 | 病例并案两段式 | 纯向量 0.8844 拉不开 → 混合 0.9422 正确并案 |
| 6.4 | 状态机即检索资格 | 比过滤器更根本的防线 |
| 6.5 | 召回天花板三层治理 | 排序救不了库里没有的东西 |
| 6.6 | 探针走完整生产路径 | 绕过归一层的探针第一版自抓 4 项失败 |
| 6.7 | 阈值实测标定 | 换模型全库重标 |
| 6.8 | 判重基准池纯净 | draft 不能当判重依据 |
| 6.9 | 影子蓝绿重建 | 不 drop-first，生产化预留 |
| 6.10 | 断言覆盖业务风险 | 全绿≠没问题：版本断言拦下过期口径 |
| 6.11 | 加权分 vs RRF 选型 | 看场景是否满足工具的前提假设 |
| 6.12 | 查询编码分对称/非对称 | 判重裸编码保对称；文档检索查询侧加 BGE 指令前缀 |
| 6.13 | LLM 生成层 | 形式引用全合法≠语义忠实：资格闸收归管道 |
| 6.14 | 药品集合规则护栏 | 高分但药品集合不一致→强制降人工闸，只拦不抬 |
| 6.19 | 部位/人群集合护栏（G-10） | 同药不同部位/人群高分误判重→第二道集合校验强制降人工闸；分组边界由标定对背书 |
| 6.15 | 病例三道硬否决 | 规则缺项挪阈值救不了，四要素是法规要素 |
| 6.16 | 部分重叠双层兜底 | 词典内→确定性拦截；词典外→LLM 拒答 |
| 6.17 | 阈值下沉 MySQL | 运行时事实源进 DB，变更四要素强制留痕 |
| 6.18 | JSON 结构契约 | 格式笼子从约定变解码级强制；coverage 核对前置 |

### 2.6 生产化路径（PoC 不做、生产必做）

| 方向 | 内容 | 动机 |
|---|---|---|
| Reranker 精排 | cross-encoder 重排 top-20 | 治双塔高分段噪声（6.2 实测） |
| 混合检索 | dense+sparse，Milvus 原生 | 病例号/CAS 号等精确实体 |
| BGE-M3 评估 | 8192 tokens/中英混合/sparse 一体 | 进口药说明书双语场景 |
| 多租户 | partition_key 物理隔离 | SaaS 化 |
| 权重校准 | 专员采纳率数据回归 | 替代手拍权重 |
| 真实数据源 | NMPA 说明书库 / WHODrug / MedDRA | 替代手写样本，词典服务化解包含匹配兜底 |

**换模型重标定（已实演验证**，详见 [model-selection-recalibration.md](model-selection-recalibration.md)）：阈值是贴着模型打分习惯画的，换模型 = 向量重建 + 阈值/容差/基线三套数字重录。2026-08-17 以 bge-small-zh-v1.5 走完蓝绿全程：影子重建 → 三模型对比标定（负对照 MiniLM 触发退出标准）→ 阈值重定 → 别名切流 → 重基线回归探针全过，工具链（calibrate.py / rebuild_shadow.py / --rebaseline）就绪。国内选型结论：默认 BGE-M3（中英混合+sparse 一体+协议干净），极限效果上 Qwen3-Embedding-4B（顺手补齐 Reranker），最终拍板靠标定集实测而非排行榜。

### 2.7 工程规范（17 条速览，每条来自真实事故）

**数据分层**：源/影子分层 · 重建必须重置同步标记 · 结构化字段存源层
**写入一致性**：写完要读必 flush（同一坑踩三次换来的军规） · 脚本幂等
**归一编码**：归一先于编码 · 两阶段占位符替换（防子串污染） · 判重只编码判别字段 · 阈值实测标定
**质检回归**：入库≠生效 · 探针只增不改 · 高分段分数是噪声 · 断言覆盖业务风险
**环境**：utf8mb4 全链路 · 不遮蔽标准库 · 补丁必须断言 · 多实例隔离显式化
