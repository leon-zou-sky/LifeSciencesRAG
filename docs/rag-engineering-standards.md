# RAG 构建工程规范（团队范本）

> 本规范每一条都来自真实事故或实测数据，不是理论抄录。
> 格式：【规范】条文 → 【事故】我们踩过的坑 →【做法】正确姿势。
> 适用于：生命科学 RAG PoC 及后续生产化项目（向量库 + 关系库双层架构通用）。

---

## 一、数据分层规范

### 1.1 源/影子必须分层，影子只放"可检索视图"

【规范】关系库（MySQL）是唯一事实源（source of truth），向量库（Milvus）是可随时重建的影子。影子只放**当前可检索**的内容；作废、已合并、草稿状态的数据留在源层审计，不进影子。

【事故】指南 2016 作废版若进影子，检索会把过时口径（IIb 弱推荐）返回给专员——合规事故。

【做法】
- 同步 SQL 硬过滤：`WHERE embedding_updated_at IS NULL AND status = '现行'`
- 状态机即防线：`现行 / 作废 / 已合并 / 草稿`，只有"现行"有检索资格
- 影子行数与源层"现行"行数必须能对账一致（PoC 实测：38 = 38）

### 1.2 重建影子必须重置同步标记

【规范】任何"drop collection 重建"操作，必须同事务重置源层同步标记。

【事故】重建脚本 drop 了 Collection 但没重置 `embedding_updated_at`，结果已同步过的块全部被跳过，影子库建好是**空的**，且无报错。

【做法】重建分支固定两行：

```python
create_collections(client)          # drop + create
cur.execute("UPDATE document_chunks SET embedding_updated_at=NULL")  # 必须配对出现
```

### 1.3 结构化字段存源层，影子只存文本+向量

【规范】判重/过滤需要的结构化字段（患者、药品、时间、tenant_id、status）存 MySQL `source_meta`，影子 payload 只放检索展示必需字段。

【事故】病例并案时，向量粗筛命中旧病例但影子 payload 里没有四要素，规则打分必须回源层取——如果当初把字段只塞进影子，规则层就断了。

【做法】两段式架构：**向量粗筛（影子）→ 结构化精排（源层）**，检索用影子、规则用源。

## 二、写入与一致性规范（本团队踩坑最多的区域）

### 2.1 军规：upsert 之后紧接着要读，必须 flush

【规范】任何"写完立刻读"的路径（验证、统计、流式判重的下一条粗筛），写后必须 `client.flush()`，或 search 显式传 `consistency_level="Strong"`。

【事故】**同一坑踩了三次**：

| 次数 | 场景 | 现象 |
|---|---|---|
| 1 | draft 探针 upsert 后搜索 | 0.95 分的行搜不到 |
| 2 | 迁移后统计行数 | stats 全 0，误以为数据丢失 |
| 3 | 病例并案流式处理 | 下一条上报搜不到上一条主病例，duplicate 误判成 new |

【根因】Milvus 默认 Bounded 一致性：写入先进增长段（growing segment），search 两层都读但**有可见性窗口**；`get_collection_stats` 只数封存段（sealed），不 flush 永远是旧值。

【做法】
```python
client.upsert(collection_name=coll, data=data)
client.flush(coll)   # 紧接着要读就必须有这行；批量导入场景可最后统一 flush
```
性能敏感的生产链路用 `search(..., consistency_level="Strong")` 代替逐次 flush。

### 2.2 所有初始化/采集脚本必须幂等

【规范】init / ingest / seed 类脚本重跑 N 次结果不变：按业务主键判重（`question_std`、`doc_type+title+version`、`case_id`），已存在跳过。

【事故】无（设计阶段立下，避免了重跑灌重复数据）。

【做法】`SELECT ... WHERE 业务键` 先行，`ON DUPLICATE KEY UPDATE` 兜底；向量侧用 upsert（同 id 覆盖）而非 insert。

## 三、归一与编码规范

### 3.1 归一必须先于编码，写入路径和读取路径是镜像

【规范】文本归一化（别名映射、错别字纠正、占位清洗）是编码的**前置步骤**，写入用什么归一，查询/探针就必须用同一个归一函数。

【事故】回归探针直接编码原始输入、绕过归一层，4 项探针失败——探针测的不是生产路径，门禁形同虚设。

【做法】探针/查询/入库三处调用同一个 `normalize_text()`，禁止任何一处私自从简。

### 3.2 别名替换必须用两阶段占位符，禁止逐条 replace

【规范】别名映射（商品名→通用名）替换必须先换占位符再统一还原，严禁循环里直接 `text.replace(alias, std)`。

【事故】"司美"是"司美格鲁肽"的别名，逐条替换把"司美格鲁肽"先替成"司美格鲁肽格鲁肽"——**子串误替换污染已入库数据**，最后洗库 + 全量重建。

【做法】
```python
# 阶段一：alias → 占位符（占位符本身不含任何别名子串）
for i, (alias, std) in enumerate(ALIASES):
    text = text.replace(alias, f"\x00{i}\x00")
# 阶段二：占位符 → 标准名
for i, (alias, std) in enumerate(ALIASES):
    text = text.replace(f"\x00{i}\x00", std)
```

### 3.3 判重向量只编码核心判别字段

【规范】用于判重的 embedding 只编码判别性字段（问询库 = `question_std`），答案、备注等稀释性文本只作 payload 存储，不进向量。

【事故】question+answer 拼一起编码，几乎原文的重复问询相似度只有 0.8442，跌破 0.85 阈值被判成"新问题"——判重逻辑完全失效。只编码 question_std 后同一条 0.9769。

【做法】编码前明确"这条向量是干嘛的"：判重向量、检索向量可以各编各的，但**一个用途一根向量，别贪**。

### 3.4 阈值是实测标定的，换模型必须重标

【规范】相似度阈值（判重 0.93/0.85、并案 0.90/0.75）只在**当前模型 × 当前数据分布**上有效。BGE-large-zh 的分数压缩在 0.83~0.92 窄带，换 embedding 模型全库阈值作废重标。

【做法】标定方法：黄金集跑分 → 看三档分布 → 定阈值 → `--record` 固化基线。模型升级走"新影子全量重建 + 黄金集重标定 + 回归过了切流"。

## 四、质检与回归规范

### 4.1 入库 ≠ 生效，回归过了才算生效

【规范】任何数据入库 / 模型变更 / 阈值调整后，必须跑黄金集回归，全过才算"生效"。CI 或定时任务自动触发，失败 exit 1 卡住发布。

### 4.2 探针三要素：固定输入 + 期望行为 + 基线分数

【规范】探针只增不改；线上 badcase 修复一个固化一条。三类断言：归一断言、档位断言、漂移断言（|实测-基线| ≤ 0.03 且 top1 不许易主）。

【做法】数量原则：**覆盖行为维度，不堆量**——9 条探针覆盖判重三档 + 归一五形态 + 权限过滤 + 文档检索，每条代表一类行为。

### 4.3 高分段分数不可区分，排序是业务问题

【规范】向量分只当召回门槛；门槛之上的排序用业务规则：意图/角色 > 权威权重 > 版本时效 > 分数。禁止拿 0.952 vs 0.951 的差值当排序依据——那是噪声。

【做法】角色画像配在租户/角色配置里（热线/医学官/PV 默认视图不同），叠乘在权威权重之上。

### 4.4 断言维度必须覆盖业务风险——全绿 ≠ 没问题

【规范】黄金集断言除分数/来源外，必须覆盖业务风险维度：**版本**（expect_version，防过期口径）、状态（防 draft/作废泄漏）、覆盖（缺口品种有告警）。

【事故】说明书双版本演练：v2023 旧版靠 0.8081 vs 0.8026 的噪声级分差抢下 top1，来源断言（同药名）和漂移断言（0.0055 < 0.03 容差）全通过——过期口径穿绿马甲溜进门。加版本断言后才被按住。

【做法】探针断言维度对着业务风险设计，不是对着方便度量设计；每次 badcase 修复时多问一句"这个风险维度有断言吗"。

## 五、工程环境规范

### 5.1 字符集 utf8mb4 全链路对齐

【规范】数据库容器初始化脚本必须显式指定 utf8mb4（`conf.d` 挂载 cnf 文件），中文注释/默认值/数据任何一环是 latin1 都会全链乱码。

【事故】MySQL 容器初始化时 client 默认 latin1，表注释截断、status 默认值乱码、已存数据全变 mojibake，重建容器才根治。同族第二坑：`docker exec ... mysql` 用 heredoc 传含全角字符的 SQL，终端编码把全角字符破坏，注释被截断——**含中文的 SQL 一律写文件再 `mysql < file.sql`，不走 heredoc**。

### 5.2 模块命名禁止遮蔽标准库

【规范】项目模块名不得与 Python 标准库同名（`collections.py`、`types.py`、`email.py`…）。

【事故】`src/collections.py` 遮蔽 stdlib `collections`，pymilvus 内部 `from collections.abc import ...` 直接炸 `ModuleNotFoundError`，报错位置离根因十万八千里。

### 5.3 批量补丁/脚本化改代码必须断言验证

【规范】任何 `str.replace` 式的批量代码修改，替换前必须 `assert old in content`，静默 no-op 不允许通过。

【事故】批量补丁的目标文本与实际文件差两个字（"向量语义检索" vs "混合检索"），replace 静默空转——guidelines Collection 根本没建，后续同步崩在半途，影子库被清成 0 行。**一次静默失败，两层库全空。**

### 5.4 多实例隔离写死在代码注释和配置里

【规范】PoC 与生产实例端口、容器前缀在代码里显式标注（如 `# PoC 实例 :19531，勿碰生产实例的 19530`），环境变量命名带项目前缀，禁止裸 ` MILVUS_URI`。
