# 验证包（Validation Package）

> GxP CSV 验证文档层：把系统的"代码+配置+输出日志"包装为审计可接受的正式验证文档。
> 方法论谱系（V 模型 IQ/OQ/PQ、SR 11-7、GAMP 5/CSA）见调研文档 2.7。

## 结构

```
docs/validation/
├── README.md            ← 本文件
├── RTM.md               ← 需求可追溯矩阵 + 已知缺口登记（Deviation Log），受控文档，人工维护
├── templates/           ← 受控模板（人工维护，改动即版本变更）
│   ├── 00_plan.md       验证总计划
│   ├── 01_IQ.md         安装确认（环境/模型指纹/配置基线）
│   ├── 02_OQ.md         运行确认（标定记录）
│   ├── 03_PQ.md         性能确认（黄金集回归）
│   └── 04_signature.md  批准签字页
└── packs/               ← 每次执行生成的归档（按 日期_模型 命名，只增不删）
    └── 2026-08-18_bge-small-zh-v1.5/
```

## 使用

```bash
# 日常回归验证（IQ+PQ，OQ 引用历史标定记录）
python scripts/gen_validation_pack.py --executor <姓名> --skip-oq

# 换模型/重标定后的全量验证（先实跑 calibrate.py，OQ 段填本次标定输出）
python scripts/gen_validation_pack.py --executor <姓名> --trigger "换模型重标定"
```

## 职责边界（机器不越过的线）

- 脚本负责：采集证据（环境指纹、SHA-256、回归输出与退出码）、填充模板、归档
- 人负责：复核证据、在签字页填写结论并签署——**脚本永不输出"批准"结论**；
  PQ 未通过时脚本 exit 1 并提示"签字页不得签署"，但拦不住人违规签字，这道线靠流程而非代码

## 业务场景 × 可审计能力实现对照（PoC 现状）

> 机制级 = 系统强制、代码保证；形态级 = 版式/流程预留，机制待生产化。
> 生产改造以实际公司 QA/IT 要求为准，本表为现状基线。

### MI 热线 / 医药代表（问询应答场景）

| 业务需要 | 实现 | 级别 | 生产改造点 |
|---|---|---|---|
| 每条答复可追溯依据（哪份文档哪个版本） | 检索输出带 source_title/version/authority；黄金集版本断言强制现行版 | 机制级 | LLM 生成层补逐句引用标注 + 答复记录落库（谁问/谁答/依据） |
| 重复问题答复口径一致 | 判重复用 approved 标准答案；基准池硬过滤 status="approved" | 机制级 | — |
| 自动判重阈值可审计 | thresholds.yaml 每条线带取值理由注释；calibrate 输出归档 OQ | 机制级 | 阈值变更走电子审批流（当前为 git 记录） |
| 拿不准的不许自动答 | 灰色带强制人工闸；召回缺口明示降级不静默凑合 | 机制级 | 人工闸处置记录结构化（当前在流程里，未落审计表） |

### PV 药物警戒（病例并案场景）

| 业务需要 | 实现 | 级别 | 生产改造点 |
|---|---|---|---|
| 并案依据符合 GVP Module VI | 四要素规则分（药品/时间窗/患者）+ 依据文本随判定输出 | 机制级 | 并案阈值随新模型重标（缺口 G-01） |
| 重复报告不删、合并留痕 | 已合并报告留 MySQL 源层 + master_case_id 关联 channels 数组 | 机制级 | 合并操作记操作人/时间（字段级审计追踪） |
| 拿不准的不许自动并 | 0.75~0.90 灰色带 → 草稿状态，PV 专员确认前不进检索 | 机制级 | — |

### 内容管理（说明书/指南版本场景）

| 业务需要 | 实现 | 级别 | 生产改造点 |
|---|---|---|---|
| 旧版作废但永久可查（留存） | 作废版本留 MySQL 标"作废"不删；影子精准摘除 | 机制级 | 保留年限策略（retention policy）形式化 |
| 过期口径不可被检索命中 | 状态机即检索资格（同步时硬过滤）+ 版本断言探针兜底 | 机制级 | — |
| 入库内容来源可追溯 | ingest 管道归档原始文件（inbox→processed）+ 文档元数据 | 机制级 | 来源文件哈希入审计链 |

### 系统治理（模型/验证场景）

| 业务需要 | 实现 | 级别 | 生产改造点 |
|---|---|---|---|
| 历史答复可复现（当时模型×阈值×数据） | 黄金集基线绑定模型版本；模型权重 SHA-256 指纹入 IQ；三方一致性硬校验 | 机制级 | 答复快照留存（每次答复记录模型/阈值版本号） |
| 换模型/改阈值走变更控制 | 四级验证门禁（标定→定线→终审→切流）+ 验证包归档 packs/ 只增不删 | 机制级 | 变更单电子化 + 电子签名（Part 11，依赖账号体系） |
| 验证证据可审计 | IQ/OQ/PQ 模板 + RTM 需求追溯 + 缺口登记（Deviation Log） | 形态级→机制级 | 模板经真实 QA 评审固化；证据防篡改（WORM 存储/哈希链） |
| 谁在何时改了哪个字段 | 未实现（无账号体系、无字段级变更日志表） | 未覆盖 | 生产必补：用户体系 + audit_log 表（who/when/old→new/reason） |

### 总结对照

- **机制级已实现**：数据留存与版本、检索资格状态机、判重/并案三档人工闸、阈值留痕、版本断言、模型指纹、验证门禁——这些不依赖账号体系，PoC 能做到真机制
- **形态级预留**：验证文档、签字页——版式和流程就位，防篡改机制待生产存储
- **未覆盖（依赖账号体系，生产必补）**：字段级审计追踪、电子签名（Part 11）、电子审批流——PoC 演示时按此口径说明
